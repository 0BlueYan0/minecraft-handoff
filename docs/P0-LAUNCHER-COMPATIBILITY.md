# P0 啟動器相容性追蹤

**最新進展：0.1.2 已改用保留原 JVM 的 Runtime Attach，在本機原 SAO 實例通過正常驗證後附加並持續保持連線；見 [原程序接入驗證](P0-RUNTIME-ATTACH.md)。以下保留 0.1.1 失敗路線的追蹤紀錄。**

使用者後續提供的 Mac latest.log，SHA-256 為 `001eff722bc285652c326d39a98ce68554c748efde4773abb06659953f058fcc`，包含以下事件：

這證明 P0 模組已在 Mac 載入，但替代啟動沒有通過原啟動器驗證。JOINED 是客戶端生命週期事件，不代表伺服器已完成驗證或允許持續遊玩。

0.1.1 不再作為可用的進服部署路徑。沒有進行前一則回覆提出的自動停止修改；它無法解決此驗證拒絕。不能從 Invalid token 單獨判定是一次性 token、到期、退出撤銷、工作階段綁定或本機驗證服務中止；需要驗證服務／啟動器的生命週期證據。

使用者確認第二次遊戲開啟時原 Triggers Client 仍開著，排除啟動器整個關閉這個解釋。進一步本機 Windows exe 字串檢查發現 `src/launcher_token.rs`、`launcher_token_expires_at`、`/api/launcher/session`、`src/heartbeat.rs`、`/api/launcher/heartbeat`、`game_foreground`、`play_seconds`。它們是獨立啟動 session／心跳的靜態線索，不能證明 Mac 這次 token 失效的確切分支，也不能證明 PID 綁定或退出撤銷。

本機 Windows main.log 只有其他啟動時間的紀錄，沒有本次 Mac 12:49–12:51 的啟動 session 狀態。下一項必要證據是 Mac 原啟動器同期的主日誌；不需要複製 token 值或完整啟動命令。取得這項證據前不再以參數重播方式要求使用者重試。

使用者另提供拒絕畫面，文字明示啟動器工作階段被拒絕（已過期或無效），並要求重新啟動 Triggers-Client、重新登入。這與先前 Invalid token 一致。

已確認：原啟動器仍開著，但它已結束對第一個遊戲的執行中狀態管理；輔助程式的新程序沒有對應的正式啟動登記紀錄。尚不能確認：後端是否由 false 心跳撤銷 token、token 的有效期限、是否一次性，或是否綁定其他啟動狀態。上述因果只能作為待驗證假設，不能寫成已證實的撤銷機制。

目前設計約束改為保留原啟動器正式啟動的原遊戲程序及其驗證工作階段。自訂功能能否透過正式擴充入口或同一程序內的接入方式實現，尚未驗證；不宣稱此約束本身就是已實作的修正。0.1.1 參數重播仍維持撤回，不要求使用者再次重跑同一路線。

後續設計的必要條件是保留合法的原啟動器驗證工作階段。先確認原啟動器是否提供正式擴充／模組允許機制，再決定接入方式；不以複製舊驗證值、修改驗證模組或偽造服務回應替代此條件。啟動器認可的原遊戲程序如何接入自訂功能，目前尚未驗證，不宣稱已找到修正。

以下保留先前實驗與驗證邊界作為歷史紀錄。

## 已確認的失敗

使用者提供的 Mac latest.log 顯示 Minecraft 1.21.4、Fabric Loader 0.20.1、Apple M1、SAOUI 2.51.10。載入清單沒有 minecraft_handoff，全文沒有 handoff 診斷。使用者進一步確認：附加 JAR 在啟動前存在，啟動後消失。

因此直接安裝在受管理 mods 目錄的方式未完成 P0 載入驗證，不能當作模組執行錯誤或記憶體不足。

## 啟動器離線檢查

本機 Windows Triggers Client 的 exe SHA-256：`518ce182b7cf6861a54c834f38cfefb57e3e2f8017df5160714a38e96ee2f79f`。

REA open_binary 確認是 x86_64 PE；深入分析因沒有配置 Ghidra／IDA provider、且 Hopper 不支援 Windows 而不可用。後續以一般離線檔案與字串檢查補充，沒有把它們當作完整反編譯或 Mac 執行證據。

可見字串包括同步目錄清理、JVM 環境變數被忽略、從 mods 外載入程式碼的 JVM 參數被忽略，以及 `_JAVA_OPTIONS`、`JAVA_TOOL_OPTIONS`、`JDK_JAVA_OPTIONS`。本機設定的 launcher_config 只見記憶體、畫面、下載及 UI 選項；在這個設定檔內沒有發現可保留附加模組的設定。這是有界檢查，不能宣稱所有版本都沒有開關。

這些線索使「原啟動器繼承環境變數，藉 fabric.addMods 加載外部 JAR」不適合作為直接交付的已知修正；未製作或要求使用者測試這個環境變數方案。

## 選擇的下一個實驗

採用使用者先前授權的替代參數啟動路線：原啟動器正常取得合法帳號與實例參數，原遊戲停在主選單；輔助程式只在記憶體中保留該次原程序的參數，等待使用者正常退出後，以同一 Java 加上外部 P0 JAR 重新啟動。

- 不修改原 launcher，不移除或替換驗證模組，不產生或偽造驗證值。
- 不讀取啟動器的帳號儲存資料，不輸出／另存完整參數；字串表示也遮蔽參數。
- 只選擇同一個系統使用者、KnotClient、完全相同實例路徑的唯一 Java 程序；有多個候選就停止。
- 沒有可靠的參數陣列時停止，不使用命令字串猜測空白／引號邊界。
- 第二次遊戲仍正常寫入原實例的遊戲日誌與設定；本工具不另建含驗證資料的日誌。
- 本實驗不保證原驗證在第一次退出後仍有效；這是必須由 Mac／實服回答的問題。

## 驗證

核心參數計畫先有 7 個失敗測試，再實作並通過。原生程序整合測試在本機 Windows 發現 ProcessHandle.Info.arguments 缺失；經 runtime 診斷及 OpenJDK 原始碼比較後，這 3 項測試改以原生能力作為前置條件，明確標記跳過，不宣稱通過。額外以可控制的 Java 子程序驗證真正的 ProcessBuilder 參數邊界與 property 傳入。

新增回歸測試重現不相關程序的 metadata 權限錯誤導致整次搜尋中止，修正為略過無法存取的程序。程式不提高權限。

最後完整建置為 34 項測試通過、3 項平台測試跳過，0 失敗；Mac 腳本通過 Bash 語法檢查。P0 原 JAR hash 保持 `71d2fa1db53c6271b17eeb501f78f29933062f926c36c444f0269fa6183fe105`。

仍需驗證：Mac 的參數存取、Java runtime 位置、第一次退出後驗證有效期，以及第二次遊戲中的 P0 初始化／連線事件。尚未完成遊戲接力。

## 獨立審查與修正

唯讀審查未發現額外的參數／憑證洩漏問題；指出啟動腳本可能先選到舊 Java。已用受控 Git Bash 測試重現 Java 17 被誤選、未探測版本及未使用有效 JAVA_HOME 的失敗，再修正為先清理 JVM option 環境、逐一探測 Java >=21、支援 JAVA_HOME 與系統註冊 runtime 後備。4 個腳本行為測試全部通過；這些是 Windows 上的命令 fixture，不是 Mac 實跑。

審查保留的驗證邊界：Mac 原生程序資料與真實 token 有效期仍待實測；只保留 Java/argv，原程序環境與工作目錄未完整擷取，故選擇實例工作目錄的相容性也待驗證；onExit 只能確認程序結束，不能證明正常退出；同一使用者惡意冒充程序與檢查後替換 JAR 不屬於本次合作式本機測試的安全邊界。遊戲接力依然未實作。
