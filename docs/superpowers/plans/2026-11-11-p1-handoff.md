# P1 Native Relay Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline in this chat. The user explicitly requested continued implementation and final Mac-host / Windows-viewer startup instructions; do not add another permission pause for routine implementation decisions.

**Goal:** Implement a real single-upstream relay prototype with native local Minecraft rendering and exclusive control, then package Mac host and Windows viewer startup paths.

**Architecture:** Keep the authenticated original host JVM. A remapped native bridge loaded by a standard agent provides a private Minecraft frontend, snapshots the host's visible state and mirrors updates, and accepts input only from its active controller. A separate viewer bootstrap uses installed game resources and an isolated instance, authenticating only to our paired relay. An authenticated TLS tunnel connects the Windows loopback Minecraft port to the Mac service.

**Tech Stack:** Java 21, Minecraft 1.21.4, Fabric Loader 0.20.1, Loom 1.10.5 / Gradle 8.12; native Minecraft packet codecs and Netty; standard Java TLS and Attach APIs.

**Spec:** `../specs/2026-11-11-minecraft-handoff-design.md` and `../../P1-VIEWER-PREFLIGHT.md`.

## Global Constraints

- One real SAO player connection, owned by the original authenticated JVM. No replayed Triggers tokens or second direct SAO login.
- Viewer writable data is isolated; no launcher account databases, cookies or private saves copied.
- Initial networking binds loopback. Remote access requires pairing authentication and pinned encrypted transport.
- Reject unsupported/unsafe protocol transitions and slow viewers without terminating the upstream host.
- Unknown custom payload replay is not assumed safe. Preserve the original authentication handler; never counterfeit its success responses.
- Runtime packets, game libraries and assets remain local dependencies; deliver only project code and startup tools.
- Capture evidence and report actual functionality/limits. A test world is not an SAO handoff.

## Review Focus

- Viewer cannot accidentally connect to the real SAO destination.
- Duplicate / late controller input cannot change host state after revocation.
- Native registry/configuration bootstrap is valid for a mid-session join.
- Snapshot and subsequent packet ordering cannot lose updates or block the original event loop.
- Pairing/token failure and viewer disconnect cannot close the authenticated upstream game.
