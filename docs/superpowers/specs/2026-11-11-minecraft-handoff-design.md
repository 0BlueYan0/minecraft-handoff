# Minecraft SAO 跨電腦接力：第一版設計

日期：2026-11-11。狀態：使用者已確認書面規格與 P0 計畫，P0 自動化驗證已通過，原啟動器／Mac 驗收待實測；遊戲接力尚未實現。

## 目標與成功定義

同一位玩家使用不同電腦上的 Minecraft 客戶端接力遊玩。切換操作電腦期間，Mac mini 到 SAO 伺服器的既有玩家連線不重新登入，伺服器不因接力產生玩家離開／加入事件。各電腦自行渲染，不使用畫面串流。

B 可以在加入後等待載入；同步完成前不取得操作權。預先連線的即時切換列為後續擴充，第一版不以零秒切換作為驗收條件。

最終目標涵蓋正常 SAO 遊玩。早期原型的模組載入、控制權模型或原版狀態測試通過，不等於已完成 SAO 接力。

## 已確認環境

- Minecraft 1.21.4、Fabric Loader 0.20.1、Java 21。
- 現有 Fabric API 為 0.119.4+1.21.4。
- 遊戲資料夾：`C:\Users\user\AppData\Roaming\.Triggers Client\instances\Sword Art Online`。
- 專用 SAO 整合包目前有 63 個頂層 JAR，包含 SAOUI 2.51.8、MCEF 和多個 companion 模組。
- 日誌顯示原模組讀取 `launcher.token`、`launcher.instance`；本機靜態分析確認有啟動器驗證及自訂通訊程式，但沒有觀察到成功進服後的完整交換流程。
- 常駐設備採用 M1 Mac mini、8 GB 統一記憶體。使用者確認原啟動器與此整合包已能在該設備正常進入 SAO 伺服器。
- 使用者接受在各電腦與 Mac 上額外安裝自行開發的 Fabric 模組。
- 原始遊戲與驗證流程保留。第一版使用原啟動器；替代參數啟動不是必要條件。

## 架構

### 帳號與連線角色（接入驗證後補充）

這個設計不能靠同一帳號再次直連真實 SAO 伺服器完成接管。真實 SAO 只有常駐端的一條上游玩家連線；A／B 是連到自有接力入口的本機渲染／操作端，不另外建立 SAO 玩家登入。

常駐端可在原啟動器正常進服並驗證成功後附加 runtime agent。操作端則必須在主選單或尚未連真實 SAO 之前進入 viewer／controller 模式，把目的地導向自有入口。不能把目前的進服後診斷附加流程當作操作端登入方案。

0.1.2 僅實作常駐端的觀察性接入，尚未實作接力入口、操作端重建或目的地導向。後續還必須驗證另一台 Triggers 啟動器是否會建立互斥的啟動 session、撤銷原會話，以及 SAO 模組是否另有獨立官方 API 存取。需要先通過這個角色／會話隔離關卡，不能由單一 JVM 附加成功推論跨機接力已成立。若操作端的原啟動流程造成會話互斥，需另行設計不向官方服務新增啟動 session 的本地顯示端啟動方式；目前沒有宣稱該替代方式已驗證。

操作電腦 A／B 上的原整合包加裝接力模組，連到 Mac 上的接力服務。Mac 上的完整 Minecraft 客戶端加裝常駐端模組，維持唯一的上游玩家連線。

常駐完整客戶端是相容性優先的起點，尚未證實可將其狀態完整匯出到新客戶端。原型必須驗證這個核心假設。

### 常駐 Minecraft

維持上游協定、原模組生命週期與 SAO 驗證。任何時候只允許一個操作來源；由接力服務決定操作電腦或無人操作狀態。控制移交時必須協調常駐客戶端的移動、物理模擬與協定回應，避免重複產生封包。

### 接力服務

維持接力工作階段、同步世代與操作權；管理經驗證的下游連線及回壓。它需要提供讓本機 Minecraft 建立遊戲狀態的入口，並處理登入／設定／遊玩階段的差異；不能假設一條 WebSocket 就能把原客戶端變成另一個客戶端。

下游身分驗證與上游原啟動器驗證分開處理。正式跨機連線使用有身分驗證的加密傳輸；早期僅限 loopback 的診斷不開放遠端入口。日誌不記錄啟動器憑證、原始自訂 payload、聊天或其他玩家資料。

### 操作端模組

載入同步資料、回報同步世代與完成狀態，在取得操作權後轉交操作。未取得操作權的客戶端不能透過自動模組回應或延遲封包改變上游狀態。

## 狀態同步原則

1. 使用一致的快照邊界加上有序增量；快照期間到達的更新不能遺失。
2. 原版世界、維度／registry、區塊、實體、位置、生命值、效果、背包與容器，依客戶端生命週期重建。
3. SAO 自訂通訊逐項確認初始化、完整狀態、增量與事件的語意。只轉送後續訊息不足以支援中途加入。
4. 持續狀態可以重建；攻擊、購買、獎勵通知、音效等一次性行為不能盲目重播。
5. 控制權只在支援的狀態已同步完成後移交。無法確認安全同步的過渡狀態，例如未完成容器操作，暫緩交接並保留原控制者。
6. 資料流採有界佇列；慢速操作端不能阻塞上游 keepalive 或造成無界記憶體增長。同步無法追上時中止該次加入，允許重試。

## 接力流程與失敗處理

正常交接：A 操作 → B 加入並載入 → B 回報對應世代已完成 → 常駐端暫停接受 A 的新操作 → 建立最終一致邊界 → 發出新控制權世代 → B 操作。

B 準備失敗不撤銷 A。A 突然斷線則撤銷它的操作權，常駐端持續維持必要協定與正常角色行為，等待 B。已失效世代的操作一律丟棄。網路傳送舊操作的清理與尚未完成的上游交換，必須在遊戲整合階段驗證；單元測試中的世代模型不是此項已完成的證據。

無人操作時不提供自動練功或防踢功能；角色仍受重力、受傷及伺服器閒置規則影響。Mac 斷網、程式崩潰、伺服器踢出或重啟仍會結束上游連線。第一版固定一台常駐主機，搬主機需要一次正常重新登入。

## 分階段驗證

### P0：載入診斷與控制權模型

交付可建置的附加 Fabric 模組、只讀診斷與獨立控制權模型。用原啟動器載入，確認附加 JAR 是否被保留，以及原整合包仍能正常遊玩。診斷只記錄本模組生命週期、連線事件、允許清單中的模組版本、JVM heap 與接力狀態；不讀取或輸出驗證值。

純控制權模型測試涵蓋同步失敗、舊世代、控制者斷線及取消準備。P0 不建立接力遊戲入口，不維持替代玩家連線，不宣稱可接管遊戲。

### P1：原版狀態的接力垂直切片

先在本機測試伺服器實作接力入口、原版狀態快照／增量、操作轉交和常駐端協調。以 A 離開後 B 加入為實際測試，不只測預先連線。伺服器日誌與連線識別證明上游未重登。

### P2：SAO 相容與實服驗證

逐項驗證驗證生命週期、自訂初始化、任務、技能、隊伍、裝備及 UI。用實際行為比對同步結果，對無法同步的狀態明確阻止交接。最後以原啟動器、完整整合包及真實 SAO 伺服器進行端到端測試。

### P3：資源與長時間穩定性

在 Mac 上量測待機、遊玩、換區域、B 同步與無人操作的程序總記憶體、CPU、記憶體壓力及網路；JVM heap 不當作總記憶體。先保留協定與模組更新正確性，再降低渲染負載。依量測結果判斷香港 VPS 或 GCP 的無頭部署；台灣 1C1G 僅在精簡代理有證據可行後評估。

## 需要原型回答的問題

- 原啟動器是否容許附加 JAR，是否會在更新時移除它。
- 原啟動器在其他裝置啟動遊戲是否影響既有上游驗證；自訂驗證是否會在遊玩中重複要求。
- 原版連線狀態可否從常駐客戶端可靠重建，哪些協定回應必須由常駐端唯一處理。
- 各 SAO 模組是否支援完整重同步，或必須增加本機快取／狀態轉接。
- 在 M1 8 GB 上維持完整模組與同步快取時，實際資源用量是否可接受。

這些是具有明確驗證出口的研究項目，不是已成立的功能保證。

## 交付與驗收

每階段提供原始碼、可建置版本、適用版本、實際通過的測試與未完成項目。安裝附加模組時先確認目標並提供可回復方式，不覆寫第三方模組。Mac 端驗證只能在實際 Mac 上完成，Windows 建置成功不得代替它。

原始資料來源：本機 README.txt、logs/latest.log、fabric.mod.json 與 SAOUI JAR 的選定類別靜態檢查；完整反編譯與實服通訊尚未完成。
